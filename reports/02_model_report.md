## Pipeline

```
raw CSV → pandas cleaning → train/test split (stratified 70/30)
       → impute (constant) → cap outliers (z=3.85, train-only)
       → feature construction (7 engineered) → one-hot + frequency encode
       → log1p → StandardScaler → XGBClassifier
```

## Performance notes

- **ROC-AUC 0.914** on a 37% positive-class dataset indicates strong
  discrimination between cancelled and non-cancelled bookings.
- Frequency encoding of `country` plus engineered features
  (`adr_per_person`, `room_type_changed`, `has_company`) add meaningful signal.
- Top predictive signals (from feature selection + domain reasoning):
  `lead_time`, `deposit_type`, `required_car_parking_spaces`,
  `total_of_special_requests`, `market_segment`, `country_freq`.

## Column requirements at inference

The prediction app accepts **any** booking CSV, not just the full Kaggle format.
Columns are handled in three tiers:

1. **Important (must be present or derivable):** `hotel`, `lead_time`,
   `arrival_date_month`, `stays_in_*_nights`, `adults`, `children`, `babies`,
   `meal`, `country`, `market_segment`, `distribution_channel`,
   `reserved_room_type`, `assigned_room_type`, `booking_changes`,
   `deposit_type`, `customer_type`, `adr`, `required_car_parking_spaces`,
   `total_of_special_requests`. If one is missing, the app lists exactly which
   important column(s) are absent.
2. **Optional (safe to default):** guest-history fields (`is_repeated_guest`,
   `previous_cancellations`, `previous_bookings_not_canceled`), `agent`,
   `days_in_waiting_list`, date-part fields, and `has_company`. Absent ones are
   filled with a neutral value (0) — equivalent to the fitted imputer's constant
   fill — and the user is warned.
3. **Derived:** `has_company` (from `company`), engineered features
   (`total_stay_nights`, `is_solo`, `adr_per_person`, `room_type_changed`, ...),
   and `country_freq` are all produced by the pipeline.

`reservation_status`, `reservation_status_date`, and `is_canceled` are not needed
for prediction; if present they are dropped before the model runs. Predictions
are re-aligned to the user's original rows via an `_original_row` marker, so rows
removed during cleaning show as blank instead of shifting results.
